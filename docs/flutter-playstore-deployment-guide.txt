KVWallet - Panduan Deploy ke Google Play Store
================================================
Dibuat: 2026-08-22
Status project saat ini:
  - Application ID masih "com.example.kv_wallet" -> WAJIB diganti, Play Store
    menolak package name com.example.*
  - Release build masih ditandatangani pakai debug key (lihat
    android/app/build.gradle.kts baris "signingConfig = signingConfigs.getByName("debug")")
    -> WAJIB dibuat keystore rilis sendiri sebelum upload ke Play Store.

Ikuti berurutan dari BAGIAN A sampai C.


BAGIAN A - SETUP PROJECT (dilakukan SEKALI di awal)
=====================================================

A.1. Tentukan Application ID unik
----------------------------------
Format kebalikan domain, contoh: com.kodevisual.kvwallet
PENTING: ID ini PERMANEN. Setelah app di-publish ke Play Store, ID ini
TIDAK BISA diganti lagi (kalau diganti, dianggap app baru, kehilangan semua
review/install lama).

File yang perlu diedit:
  android/app/build.gradle.kts
    baris: applicationId = "com.example.kv_wallet"
    ganti jadi: applicationId = "com.kodevisual.kvwallet"  (atau ID pilihanmu)

  android/app/src/main/AndroidManifest.xml
    baris: android:label="kv_wallet"
    ganti jadi nama yang mau ditampilkan di HP, misal: android:label="KVWallet"

Setelah ganti applicationId, jalankan:
  flutter clean
  flutter pub get


A.2. Generate keystore (kunci penandatanganan rilis)
------------------------------------------------------
Keystore ini WAJIB disimpan aman & di-backup ke tempat lain (Google Drive,
password manager, dll). Kalau file ini hilang, kamu TIDAK BISA update app
itu lagi selamanya di Play Store -- harus publish sebagai app baru dari nol.
JANGAN commit file keystore atau passwordnya ke git.

Jalankan command ini dari folder project (butuh Java JDK, biasanya sudah
ikut terinstall bareng Android Studio):

  keytool -genkey -v -keystore kvwallet-release.keystore -alias kvwallet -keyalg RSA -keysize 2048 -validity 10000

Akan diminta isi:
  - Password keystore (ingat baik-baik, minimal 6 karakter)
  - Nama, organisasi, kota, negara (boleh diisi asal, tidak terlalu penting)
  - Password untuk key alias "kvwallet" (boleh sama dengan password keystore)

Pindahkan file kvwallet-release.keystore ke folder:
  android/app/kvwallet-release.keystore

Tambahkan ke android/.gitignore (buat file baru kalau belum ada) supaya
tidak ke-commit ke git:
  key.properties
  *.keystore
  *.jks


A.3. Buat file android/key.properties
----------------------------------------
Buat file baru: android/key.properties (JANGAN commit ke git, sudah
di-ignore di langkah A.2)

Isi:
  storePassword=<password keystore yang tadi diisi>
  keyPassword=<password key alias yang tadi diisi>
  keyAlias=kvwallet
  storeFile=kvwallet-release.keystore


A.4. Update android/app/build.gradle.kts
--------------------------------------------
Tambahkan di BAGIAN PALING ATAS file (sebelum blok "plugins"):

  import java.util.Properties
  import java.io.FileInputStream

  val keystoreProperties = Properties()
  val keystorePropertiesFile = rootProject.file("key.properties")
  if (keystorePropertiesFile.exists()) {
      keystoreProperties.load(FileInputStream(keystorePropertiesFile))
  }

Ganti seluruh blok berikut:

  buildTypes {
      release {
          // TODO: Add your own signing config for the release build.
          // Signing with the debug keys for now, so `flutter run --release` works.
          signingConfig = signingConfigs.getByName("debug")
      }
  }

Menjadi:

  signingConfigs {
      create("release") {
          keyAlias = keystoreProperties["keyAlias"] as String
          keyPassword = keystoreProperties["keyPassword"] as String
          storeFile = keystoreProperties["storeFile"]?.let { file(it) }
          storePassword = keystoreProperties["storePassword"] as String
      }
  }
  buildTypes {
      release {
          signingConfig = signingConfigs.getByName("release")
      }
  }

Catatan: file key.properties dibaca dari root folder "android/", karena
android/key.properties itu root project-nya Gradle (bukan folder android/app/).


A.5. Bump versi sebelum build
---------------------------------
Edit pubspec.yaml baris "version:", format version+buildNumber, contoh:
  version: 1.0.0+1
Setiap kali upload build baru ke Play Store, buildNumber (angka setelah +)
WAJIB dinaikkan (Play Store menolak upload dengan versionCode yang sama
atau lebih kecil dari yang sudah pernah di-upload).


A.6. Build App Bundle rilis
--------------------------------
  flutter build appbundle --release

Hasil ada di:
  build/app/outputs/bundle/release/app-release.aab

Ini file yang di-upload ke Play Console (BUKAN apk).

(Opsional) Kalau mau APK juga buat testing manual/sideload:
  flutter build apk --release
Hasil: build/app/outputs/flutter-apk/app-release.apk

Tes dulu APK release ini di HP fisik sebelum upload, pastikan:
  - Login/register jalan normal ke backend production (kodevisual.com)
  - Tidak ada crash saat buka semua menu (Dashboard, Transaksi, Ringkasan,
    Portfolio, Settings)


BAGIAN B - AKUN GOOGLE PLAY CONSOLE (dilakukan sekali)
=========================================================

B.1. Daftar akun
--------------------
Buka https://play.google.com/console
Daftar akun developer, bayar biaya registrasi $25 USD (sekali seumur hidup
akun, bukan langganan tahunan).
Verifikasi identitas (KTP/paspor) & tunggu approval (biasanya beberapa jam
sampai 2 hari).

B.2. Buat aplikasi baru
----------------------------
Di Play Console: All apps -> Create app
  - App name: KVWallet (atau nama final pilihanmu)
  - Default language: Indonesian
  - App or game: App
  - Free or paid: Free
  - Isi declarations yang diminta (checkbox kebijakan Play)

B.3. Isi Store Listing (Main store listing)
------------------------------------------------
Wajib diisi sebelum bisa publish:
  - Short description (max 80 karakter)
  - Full description (max 4000 karakter)
  - App icon 512x512 PNG (bisa export dari assets/branding/icon.png,
    tinggal resize ke 512x512)
  - Feature graphic 1024x500 PNG/JPG (banner, belum ada -- perlu didesain)
  - Screenshot minimal 2, resolusi HP (bisa screenshot langsung dari app
    yang jalan di emulator/HP)
  - Kategori app (misal: Finance)
  - Contact email

B.4. Content rating questionnaire
--------------------------------------
Play Console -> Policy -> App content -> Content ratings
Isi kuesioner (KVWallet app finance biasa, tidak ada konten dewasa/kekerasan,
kemungkinan besar dapat rating "Everyone").

B.5. Data safety form
--------------------------
Play Console -> Policy -> App content -> Data safety
Deklarasikan data yang dikumpulkan app ini, minimal:
  - Email address (untuk login)
  - Financial info (data transaksi, saldo, portfolio)
Jelaskan juga apakah data dienkripsi saat transit (ya, karena API pakai
HTTPS) dan apakah user bisa minta hapus data.

B.6. Privacy Policy URL
----------------------------
WAJIB ada halaman privacy policy yang bisa diakses publik (URL apa saja,
bisa halaman statis sederhana di website kodevisual.com). Play Store tidak
akan approve app tanpa ini karena app menangani data finansial pengguna.

B.7. Target audience & Ads
--------------------------------
Play Console -> Policy -> App content -> Target audience
Isi target umur pengguna (kemungkinan 18+ untuk app finance, atau umum
tergantung kebijakan internal).
Ads declaration: pilih "No, my app does not contain ads" kalau memang tidak
ada iklan.


BAGIAN C - UPLOAD & PUBLISH
==================================

C.1. Buat testing track dulu (rekomendasi)
------------------------------------------------
Play Console -> Testing -> Internal testing -> Create new release
  - Upload file app-release.aab dari langkah A.6
  - Isi release notes (catatan rilis, misal "Rilis awal KVWallet")
  - Tambahkan email tester (email Gmail siapa saja yang mau ikut testing,
    termasuk email kamu sendiri)
  - Save -> Review release -> Start rollout to Internal testing

C.2. Install & tes dari link internal testing
----------------------------------------------------
Play Console akan kasih link "opt-in URL" untuk internal testing. Buka link
itu di HP pakai akun Gmail yang sudah didaftarkan sebagai tester, install
app dari Play Store (bukan sideload APK), lalu tes semua fitur.

C.3. Promote ke Production
--------------------------------
Kalau sudah yakin tidak ada bug, di Play Console:
  Testing -> Internal testing -> pilih release yang sudah dites ->
  "Promote release" -> pilih "Production"
Isi rollout percentage (bisa mulai 100% kalau app baru/kecil).
Submit -> tunggu review Google (biasanya 1-3 hari untuk app baru,
bisa lebih lama untuk app finance karena diperiksa lebih ketat).

C.4. Update untuk rilis berikutnya
-----------------------------------------
Setiap kali mau update app yang sudah live:
  1. Naikkan buildNumber di pubspec.yaml (contoh: 1.0.0+1 -> 1.0.1+2)
  2. flutter build appbundle --release
  3. Upload .aab baru ke Play Console (bisa langsung ke Production track
     atau lewat Internal testing dulu)
  4. Isi release notes
  5. Submit
