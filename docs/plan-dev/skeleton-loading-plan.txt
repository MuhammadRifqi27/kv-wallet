- Efek yang dipakai: PULSE warna (interpolasi antara warna dasar &

  di-maintain (cuma `Color.lerp` + `AnimationController`, tanpa
  matematika gradient/Transform), efeknya tetap jelas terbaca sebagai
  "loading", dan konsisten dengan filosofi AppLoadingIndicator yang
  juga animasi sederhana (staggered dot, bukan efek kompleks). Gradient
  sweep bisa jadi v2 enhancement kalau nanti dirasa kurang "premium" —
  dicatat di BAGIAN 6, bukan blocker sekarang.
- Komponen jadi SATU file baru: lib/shared/widgets/skeleton_loader.dart
  — mengikuti konvensi list_states.dart yang juga membundel beberapa
  widget terkait (scrollableCenter, ListEmptyState, ListErrorState)
  dalam satu file, bukan satu file per class.
- Kebijakan MANA yang diganti skeleton vs TETAP seperti sekarang
  (supaya rollout tidak asal-ganti semua loading state):
  - Loading state utama halaman (full-page/section, `.when(loading:)`
    pada AsyncValue yang isinya list/card konten) -> DIGANTI skeleton.
  - Loading kecil INLINE di dalam form (dropdown kategori/akun lagi
    fetch, dst — pola `LinearProgressIndicator` di transaction_form_
    page.dart:277,298 dkk) -> TETAP, skeleton berlebihan untuk elemen
    sekecil itu. Ini konsisten dengan aturan AppLoadingIndicator sendiri
    (lihat class doc-nya: "full-page/section" vs "small inline").
  - Spinner tombol submit/proses (PIN pages, PrimaryButton.isLoading)
    -> TETAP. Skeleton cuma relevan untuk "konten sedang dimuat", bukan
    "aksi sedang diproses".
  - splash_page.dart -> TETAP (pre-auth, tidak ada bentuk konten untuk
    di-skeleton-kan).
  - Footer "load more" pagination (transaction_list_page.dart:187)

BAGIAN 2 — DESAIN KOMPONEN REUSABLE
-----------------------------------------
Semua di lib/shared/widgets/skeleton_loader.dart.

2.1. `SkeletonShimmer` — StatefulWidget ambient, MEMBUNGKUS satu blok
     layout skeleton (bukan dipasang per-box). Punya SATU
     `AnimationController` (`vsync: this`, `duration: ~1200ms,
     repeat(reverse: true)`), diekspos ke descendant lewat
     `InheritedNotifier<Animation<double>>` (pola standar Flutter buat
     "satu controller, banyak consumer di bawahnya" — supaya tidak
     perlu bikin AnimationController baru per kotak skeleton, cukup
     SATU per instance `SkeletonShimmer`, N kotak di bawahnya ikut
     berdenyut sinkron).
     - Constructor: `SkeletonShimmer({required Widget child})`.
     - Statis `SkeletonShimmer.of(context)` — dipakai `SkeletonBox`
       buat baca nilai animasi saat ini.
     - HORMATI `MediaQuery.of(context).disableAnimations` (flag
       accessibility "reduce motion" bawaan Flutter) — kalau true,
       render langsung warna dasar statis tanpa menjalankan
       AnimationController sama sekali. Terhubung dengan kerja
       aksesibilitas yang baru selesai di
       docs/ide-improvement-fitur-existing.txt BAGIAN I.
     - Dispose controller saat widget di-unmount (pola sama seperti
       AppLoadingIndicator) — TIDAK dipasang ambient sekali di root
       app (beda dari ShowcaseView.register()), supaya animasi cuma
       jalan/nge-tick selagi ada skeleton yang benar-benar tampil di
       layar, bukan terus-menerus seumur hidup app.

2.2. `SkeletonBox` — StatelessWidget, primitif bentuk dasar.
     - Params: `width` (nullable — null berarti `double.infinity`),
       `height` (required), `borderRadius` (default kecil, mis. 6),
       `shape` (`BoxShape.rectangle` default, `BoxShape.circle` buat
       avatar/icon-bubble — kalau circle, `borderRadius` diabaikan
       sama seperti API `Container`/`BoxDecoration` biasa).
     - `build()` panggil `SkeletonShimmer.of(context)` buat ambil nilai
       animasi, isi `Container` dengan `Color.lerp(skeletonBase,
       skeletonHighlight, animationValue)`.
     - Harus dipanggil DI DALAM `SkeletonShimmer` (bukan berdiri
       sendiri) — kalau tidak ada ancestor `SkeletonShimmer`,
       `SkeletonShimmer.of(context)` throw assertion error yang jelas
       (fail fast, bukan silent fallback ke warna statis — supaya
       salah pakai ketahuan pas development, bukan lolos ke user
       sebagai kotak abu-abu diam yang terlihat seperti bug lain).

2.3. Token warna baru di AppColors — `skeletonBase` & `skeletonHighlight`
     (theme-aware, pola sama seperti getter lain, flip lewat
     `_isDark`). BUKAN pakai ulang `border`/`surface` apa adanya —
     kotak skeleton perlu FILL solid yang jelas kelihatan beda dari
     background/card di sekitarnya (bukan cuma warna garis tepi), jadi
     butuh kalibrasi sendiri. Nilai hex PERSIS ditentukan saat
     implementasi, diverifikasi manual di kedua tema (pola sama seperti
     `_infoColor` di savings_goal_style.dart — "Verified against both
     theme backgrounds").

2.4. `SkeletonListTile` — composite, meniru bentuk kartu list-item yang
     berulang di ~9 halaman (icon bubble bulat 40x40 + 2 baris teks
     [judul lebih lebar, subjudul lebih pendek] + opsional kotak
     trailing kanan buat nominal/ikon aksi), dibungkus shell yang SAMA
     persis dengan kartu list asli (`Material` + `Container` warna
     `AppColors.surface`, border `AppColors.border`, radius 14) supaya
     tidak ada lompatan layout waktu data asli muncul menggantikan.
     - Params: `hasTrailing` (bool, default true).

2.5. `skeletonListTiles({int count = 6, bool hasTrailing = true})` —
     fungsi top-level (pola sama seperti `scrollableCenter()` di
     list_states.dart, bukan class), balikin SATU `SkeletonShimmer`
     yang membungkus `count` buah `SkeletonListTile` + `SizedBox(height:
     8)` sebagai separator — dipakai langsung sebagai isi `loading:`
     buat halaman-halaman list generik (BAGIAN 3). `count` default 6
     dipilih supaya biasanya mengisi 1 layar penuh tanpa terlalu
     panjang.

2.6. Skeleton BESPOKE per halaman (Dashboard, Summary, dst — bentuk
     kontennya beda-beda, tidak generik) DIBANGUN NANTI di masing-
     masing file halaman sebagai private widget lokal (mis.
     `_DashboardSkeleton` di dashboard_page.dart), disusun dari
     `SkeletonShimmer` + `SkeletonBox` langsung — BUKAN masuk ke
     skeleton_loader.dart. Ini konsisten dengan pola yang sudah ada:
     `_DashboardEmptyState`/state lokal lain juga didefinisikan di
     file halamannya masing-masing, bukan di shared widgets.

BAGIAN 5 — HAL YANG PERLU DIPERHATIKAN
-----------------------------------------
1. Dark mode: `skeletonBase`/`skeletonHighlight` WAJIB diverifikasi
   manual di kedua tema (toggle dari Profile) sebelum dianggap selesai
   — jangan cuma percaya angka hex tanpa lihat langsung, sama seperti
   pola verifikasi warna lain di app ini.
2. PENTING — pull-to-refresh vs initial load: beberapa controller
   (`refresh()` methods, pola `state = const AsyncLoading(); state =
   await AsyncValue.guard(...)`) TIDAK memakai `.copyWithPrevious(state)`
   saat set ulang ke `AsyncLoading` — artinya `RefreshIndicator`
   (pull-to-refresh manual) KEMUNGKINAN BESAR memicu branch `loading:`
   yang SAMA dengan cold-start, bukan cuma nampilin spinner kecil di
   atas konten yang sudah ada. Ini perilaku YANG SUDAH ADA sekarang
   (bukan diperkenalkan skeleton), tapi dengan AppLoadingIndicator yang
   kecil, efeknya nyaris tidak terasa — begitu diganti skeleton
   full-layar, "kedip ke skeleton" tiap kali pull-to-refresh bisa
   terasa mengganggu/berlebihan. WAJIB dicek per halaman saat rollout
   (BAGIAN 3): kalau memang mengganggu, pertimbangkan tambah
   `.copyWithPrevious(state)` di `refresh()` controller terkait supaya
   data lama tetap tampil selama refresh (perbaikan terpisah & kecil,
   bukan bagian dari komponen skeleton itu sendiri).
3. Aksesibilitas: `MediaQuery.disableAnimations` WAJIB dihormati
   (BAGIAN 2.1) — user yang mengaktifkan "reduce motion" di sistem
   tidak boleh lihat animasi pulse.
4. Performa: satu `SkeletonShimmer` per BLOK layout (bukan per kotak)
   — `skeletonListTiles()` sudah didesain begitu (BAGIAN 2.5). Kalau
   satu halaman punya beberapa blok bespoke terpisah (mis. Dashboard:
   net worth + stat grid + savings goal), masing-masing boleh punya
   `SkeletonShimmer` sendiri — TIDAK sinkron sempurna antar blok, efek
   visual minor, bukan blocker (dicatat di sini supaya bukan kejutan
   saat implementasi).
5. Layout shift: bentuk & tinggi skeleton harus mendekati bentuk asli
   (BAGIAN 2.4's shell yang sama persis) supaya transisi skeleton ->
   data tidak melompat.
