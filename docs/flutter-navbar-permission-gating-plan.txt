PLAN - NAVBAR & MENU SESUAI MONEY MANAGEMENT PERMISSIONS
=================================================================
Dibuat: 2026-08-25
Update: 2026-08-25 (permission key final + ganti pendekatan jadi "lock &
        blur", bukan sembunyikan tab)
Status: DRAFT PLAN - belum diimplementasikan, siap eksekusi.

Tujuan: tab di bottom navbar (Dashboard, Transaksi, Ringkasan, Portfolio,
Settings) tetap semua kelihatan (konsisten, tidak menghilang), tapi tab yang
tidak diizinkan permission user tampil ke-BLUR/dim + ada indikator lock, dan
kalau di-tap diarahkan ke halaman Upgrade Membership alih-alih ke fitur
aslinya. Ini pendekatan freemium yang umum: tunjukkan apa yang "hilang"
biar user termotivasi upgrade, bukan sembunyikan begitu saja.

Menu di dalam Settings (Kategori, Provider Investasi, Siklus Gajian) TIDAK
digating sama sekali — tetap terbuka untuk semua user (keputusan eksplisit,
lihat BAGIAN 0).

Sumber data: `UserModel.moneyManagementPermissions` (List<String>) sudah
ada & di-parse dari `money_management_permissions` di response
`/auth/me`, `/auth/login`, `/auth/register` — tidak perlu API baru.
`UserModel.hasPermission(String)` juga sudah ada
(lib/data/models/user_model.dart).

BAGIAN 1 - PENDEKATAN TEKNIS
==================================

1.1. Kenapa bukan hapus branch dari StatefulShellRoute, dan bukan juga
      sembunyikan destination dari NavigationBar
------------------------------------------------------------------------
`app_router.dart` pakai `StatefulShellRoute.indexedStack` dengan 5 branch
tetap (lihat komentar di main_shell.dart: "note the branch order there must
match the destination order here"). Karena keputusan produknya sekarang
"tampilkan tapi kunci" (bukan sembunyikan), branch & destination TETAP 5
selalu — tidak perlu index remapping atau filter sama sekali. Ini
menyederhanakan implementasi dibanding rencana sebelumnya (yang sempat
mempertimbangkan hide+remap).

1.2. main_shell.dart - render locked state + intercept tap
------------------------------------------------------------
Ubah `MainShell` jadi `ConsumerWidget`, baca
`ref.watch(authControllerProvider).user`. Definisikan daftar destinasi
lengkap dengan permission key masing-masing (index harus tetap sinkron
dengan urutan branch di app_router.dart, seperti sekarang):

  const _destinations = [
    (permission: 'dashboard', icon: Icons.dashboard_outlined, selectedIcon: Icons.dashboard_rounded, label: 'Dashboard'),
    (permission: 'transactions', icon: Icons.receipt_long_outlined, selectedIcon: Icons.receipt_long_rounded, label: 'Transaksi'),
    (permission: 'summary', icon: Icons.pie_chart_outline_rounded, selectedIcon: Icons.pie_chart_rounded, label: 'Ringkasan'),
    (permission: 'portfolio', icon: Icons.account_balance_wallet_outlined, selectedIcon: Icons.account_balance_wallet_rounded, label: 'Portfolio'),
    (permission: 'settings', icon: Icons.settings_outlined, selectedIcon: Icons.settings_rounded, label: 'Settings'),
  ];

Untuk tiap destination, cek `user.hasPermission(d.permission)`:
  - Kalau diizinkan: `NavigationDestination` normal seperti sekarang.
  - Kalau tidak: bungkus icon-nya pakai widget baru `_LockedNavIcon`
    (Opacity ~0.4 + badge kecil ikon gembok di pojok kanan-atas icon, pakai
    `Stack` + `Positioned`), label tetap ditampilkan (jangan ikut di-dim
    total biar tetap kebaca ini fitur apa).

`onDestinationSelected(index)`:
  - Kalau `user.hasPermission(_destinations[index].permission)` true:
    jalan seperti biasa — `navigationShell.goBranch(index, initialLocation:
    index == navigationShell.currentIndex)`.
  - Kalau false: JANGAN pindah branch (selectedIndex tetap di tab
    sekarang). Tampilkan SnackBar singkat ("Fitur ini butuh upgrade
    membership") lalu `context.push('/settings/membership')`.

Catatan risiko: `/settings/membership` itu nested di bawah branch
'/settings', yang route-nya sendiri butuh permission 'settings'. Karena
'settings' SELALU ada di default permission free-user (lihat contoh di
docs/pin-and-membership-plan-api-reference.md), jalur upgrade ini aman
untuk kondisi normal. TAPI kalau suatu saat ada role yang bahkan tidak
punya 'settings', user itu tidak akan pernah bisa reach halaman upgrade
dari navbar manapun (tab Settings sendiri juga locked). Untuk v1 diasumsikan
tidak terjadi (settings selalu granted by default); kalau ternyata bisa
terjadi, perlu route upgrade yang berdiri sendiri di luar shell (misal
top-level `/upgrade`, tidak nested di /settings).

1.3. app_router.dart - redirect guard (defense-in-depth)
------------------------------------------------------
Tambah pengecekan permission di dalam `redirect` callback (bagian
`AuthStatus.authenticated`, setelah PIN gate lolos), buat jaga-jaga kalau
ada yang nyasar ke route locked lewat cara lain (deep link, state
tersimpan sebelum plan berubah, dsb) — BUKAN jalur utama (jalur utama
pencegahannya di 1.2, intercept sebelum `goBranch` dipanggil):

  const _routePermissions = {
    '/home': 'dashboard',
    '/transactions': 'transactions',
    '/summary': 'summary',
    '/portfolio': 'portfolio',
    '/settings': 'settings',
  };
  final requiredPermission = _routePermissions[state.matchedLocation];
  if (requiredPermission != null && !(authState.user?.hasPermission(requiredPermission) ?? false)) {
    return '/settings/membership';
  }

Catatan: kalau redirect ini kena pas user justru SEDANG di '/settings/...'
(termasuk '/settings/membership' sendiri) dan ternyata tidak punya
permission 'settings' — bisa infinite loop (redirect ke '/settings/
membership' yang notabene juga di bawah '/settings'). Karena 'settings'
diasumsikan selalu granted (lihat 1.2), risiko ini rendah untuk sekarang,
tapi tetap dicatat sebagai risiko yang sama seperti di 1.2 — kalau nanti
ternyata ada role tanpa 'settings', redirect guard ini juga perlu direvisi
bareng dengan solusi route '/upgrade' top-level itu.

1.4. settings_page.dart - TIDAK ADA PERUBAHAN
------------------------------------------------
Sesuai keputusan BAGIAN 0: "Kategori", "Provider Investasi", "Siklus
