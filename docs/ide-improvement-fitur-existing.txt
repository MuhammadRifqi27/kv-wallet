IDE IMPROVEMENT — FITUR YANG SUDAH JALAN (BUKAN MODUL BARU)
=============================================================

Beda dari docs/ide-pengembangan-100.txt (yang isinya 550 ide MODUL/
FITUR BARU) — dokumen ini fokus ke PERBAIKAN fitur yang SUDAH
diimplementasikan dan jalan di production sekarang: bug kecil, state
yang belum di-handle, inkonsistensi pola antar-layar, gap dark mode/
l10n, dan celah UX. Disusun dari audit menyeluruh ke seluruh
lib/features/* + lib/core/* + lib/shared/widgets/*, semua temuan
sudah diverifikasi baca kode langsung (bukan tebakan), dengan
referensi file:line supaya gampang ditindaklanjuti.

Bukan roadmap resmi — kumpulan temuan untuk disaring & diprioritaskan,
sama seperti dokumen 550-ide sebelumnya.


BAGIAN A — BUG PRIORITAS TINGGI
---------------------------------------
1. ✅ **Bug pola `Material`/`ListTile` — ditemukan di 8 lokasi berbeda,
   akar masalah sama.** `ListTile`/`SwitchListTile` dibungkus langsung
   di dalam `Container(decoration: BoxDecoration(color: ...))` tanpa
   `Material` widget di antaranya, sehingga ink-splash-nya
   berpotensi tidak kelihatan & Flutter debug assertion "ListTile
   background color or ink splashes may be invisible" muncul terus-
   menerus. Lokasi:
   - lib/shared/widgets/settings_tile.dart:18-38 — dipakai di 14
     tempat (profile_page.dart baris 196,204,211,230,237,252,260,
     267,274,282,289,302 + edit_profile_page.dart:152,159).
   - lib/features/profile/presentation/profile_page.dart:493-499
     (`_BiometricToggleTile`).
   - lib/features/master_data/presentation/payroll_settings_page.dart:
     104-123 (toggle akhir bulan).
   - lib/features/portfolio/presentation/portfolio_form_page.dart:
     157-176 (toggle akun investasi).
   Perbaikan: bungkus tiap `ListTile`/`SwitchListTile` dengan
   `Material(color: Colors.transparent, child: ...)` di dalam
   `Container`-nya, atau refactor `SettingsTile` sendiri supaya
   sudah include `Material` lalu 3 lokasi lain reuse widget itu.
   Area yang SUDAH BENAR (pola pembanding): `_SavingsGoalsCard`
   (dashboard_page.dart), `_GoalCard`/`_PlanCard`
   (savings_goal_list_page.dart, membership_plans_page.dart),
   `_AssetRow` (investment_dashboard_page.dart) — semua pakai
   `Material` + `InkWell` dengan benar.

2. ✅ **Kontras teks gagal di dark mode — bug nyata, bukan cuma debug-
   warning.** `_AdvisorTile` (summary_page.dart:746-770) pakai
   background `AppColors.primaryLight` (theme-aware, jadi ungu gelap
   di dark mode) tapi teksnya `AppColors.primaryDark` — warna TETAP
   `Color(0xFF333333)` yang menurut doc comment-nya sendiri
   (app_colors.dart:36-38) memang cuma didesain untuk teks DI ATAS
   `primaryGradient`, bukan di atas `primaryLight`. Hasilnya teks
   nyaris hitam di atas kartu ungu gelap — tidak terbaca. Perbaikan:
   ganti ke `AppColors.textPrimary`.

3. ✅ **Kontras global di SEMUA `ElevatedButton` saat dark mode.**
   lib/core/theme/app_theme.dart:92-95 — `foregroundColor: Colors.
   white` hardcode di atas `backgroundColor: AppColors.primary`.
   Di light mode primary = merah marun gelap (kontras bagus dengan
   putih), tapi di dark mode primary = pink pastel terang
   (app_colors.dart:94) — teks putih di atas pink muda nyaris tidak
   kebaca (gagal WCAG AA). Ini GLOBAL, ngaruh ke SEMUA tombol utama
   di seluruh app saat dark mode aktif. Pola sama berulang di:
   - lib/shared/widgets/filter_pill_bar.dart:56,64,70 (pill terpilih).
   - lib/shared/widgets/month_period_selector.dart:84,92 (sel bulan
     terpilih).
   - lib/features/emergency_fund/presentation/
     emergency_fund_calculator_page.dart:250 (`_MultiplierChip`).
   - lib/features/fire_calculator/presentation/fire_calculator_page.
     dart:343 (`_ReturnRateChip`).
   Perbaikan: tambah token `AppColors.onPrimary` yang theme-aware
   (mis. tetap putih di light, tapi teks gelap/`textPrimary` di dark),
   pakai di semua 5 lokasi ini sekaligus.

4. ✅ **Parsing nominal rupiah salah untuk input pakai titik ribuan.**
   Ditemukan di savings_goal_form_page.dart:97,185,
   savings_goal_detail_page.dart:403,509,
   emergency_fund_calculator_page.dart:47,220,
   fire_calculator_page.dart (input manual serupa),
   transaction_form_page.dart:125, budget_form_page.dart:73,
   recurring_form_page.dart:144 — semua pakai idiom yang sama:
   `value.replaceAll(RegExp(r'[^0-9.]'), '')` lalu `double.parse`.
   Karena `formatRupiah` menampilkan titik sebagai pemisah ribuan
   ("Rp 1.000.000"), user yang ngetik "1.000.000" bisa gagal parse
   (banyak titik) atau — lebih parah — "1.000" ke-parse jadi `1.0`
   (nominal 1000x lebih kecil) TANPA error apa pun. Perbaikan: strip
   titik/koma sebagai pemisah grouping SEBELUM parse, atau batasi
   input via `inputFormatters` digit-only. Sekalian jadi kandidat
   kuat untuk 1 helper `parseRupiahInput()` bersama (lihat BAGIAN M).

5. ✅ **Riwayat transaksi diam-diam cuma nampilin halaman 1.**
   lib/data/repositories/transaction_repository.dart:15-33 — request
   ke `getTransactions()` tidak pernah kirim parameter `page`, dan
   `parseListResponse` (json_parsing.dart:24-28) buang info
   `current_page`/`last_page`/`total` dari response Laravel
   paginator. Filter default "Semua" (transaction_list_controller.
   dart:45) berarti transaksi lama otomatis TIDAK BISA DIAKSES lagi
   begitu lewat 1 halaman backend — tidak ada "load more"/infinite
   scroll di transaction_list_page.dart:106-121. Lebih parah lagi,
   ringkasan chip total (`_SummaryRow`) menghitung dari SELURUH data
   terfilter, sementara list yang kelihatan cuma halaman 1 — angka
   ringkasan tidak match sama isi layar. Perbaikan: track & kirim
   `page`, tambah infinite scroll/"muat lebih banyak".

6. ✅ **`dashboard_controller.dart:21-35` — refresh bisa gagal total
   kalau proses recurring gagal.** `refresh()` await
   `recurringRepositoryProvider.processDue()` TANPA try/catch SEBELUM
   set `state = AsyncLoading()`/`AsyncValue.guard(...)`. Kalau
   `processDue()` throw, seluruh method reject dan Dashboard diam-diam
   tetap nampilin data lama — pull-to-refresh kelihatan seperti tidak
   ngapa-ngapain, tanpa pesan error. Perbaikan: bungkus panggilan
   `processDue()` sendiri dengan try/catch (sesuai niat "best-effort"
   yang sudah ada di komentar kodenya).
